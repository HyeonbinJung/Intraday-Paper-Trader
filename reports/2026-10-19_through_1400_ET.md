## Why missing and how to prevent recurrence

- The GitHub Actions schedule has been configured for 10-minute intervals, but GitHub-hosted cron **may be delayed or dropped**. Scheduled executions must be confirmed by actual run IDs; a workflow YAML definition is not proof of minute-level coverage.
- One manual run was lost on push because main advanced after job checkout. The newer workflow includes \`git pull --rebase origin main\` before push; this fix successfully passed the subsequent run #3, but not every future conflict is eliminated.
- A single GitHub Actions runner evaluates roughly one minute at a time during a short-lived job; it is **not** a 24/7 process or guaranteed real-time tick/1-minute execution engine.
- Persist an explicit no-data/missed-batch status rather than making fabricated trades.
